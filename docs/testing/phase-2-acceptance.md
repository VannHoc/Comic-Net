Có thêm `buckets/.rustfs-cas.lock` sau mount; tên và vị trí phù hợp lock nội bộ, chưa có bằng chứng độc lập về nội dung của lock. [Tài liệu scanner RustFS](https://github.com/rustfs/rustfs/blob/main/docs/operations/scanner-runtime-controls.md) mô tả bloom cycle/usage state/cache và pause ledger; [tài liệu lifecycle](https://github.com/rustfs/rustfs/blob/main/docs/operations/cluster-lifecycle-operations.md) mô tả marker unclean shutdown và pool metadata. Đây là **suy luận phù hợp với hoạt động nội bộ**, không phải cách chứng minh bằng cách bỏ 9 file khỏi manifest.

Kiểm tra độc lập: 609 payload khớp SHA cũ, 200 URL ảnh trả nội dung, 3 ảnh decode, SQL restore không có orphan/pointer sai; log phục hồi không ghi lỗi checksum/corrupt. Một yêu cầu QA báo `SignatureDoesNotMatch` là lỗi chữ ký request, không chỉ ra file hỏng. Bản sao volume sau khi tắt RustFS có 626/626 hash khớp manifest *mới* của chính nó. **Kết luận:** chưa phát hiện hư hỏng dữ liệu truyện; thay đổi 9 file có dấu hiệu cập nhật runtime bình thường. Phép so byte với snapshot ban đầu vẫn **FAIL**; muốn xác nhận sâu mọi record metadata cần admin scanner/heal status trên đúng bản RustFS 1.0.4 mà không sửa/xóa `.rustfs.sys`.
