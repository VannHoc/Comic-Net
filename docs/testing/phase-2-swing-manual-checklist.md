# Checklist nghiệm thu Java Swing trong NetBeans — Phase 2

**Trạng thái: CHƯA KIỂM CHỨNG trên cửa sổ Swing.** Các bước dưới đây là ca kiểm thử cần người dùng thực hiện; sự tồn tại của nút hoặc test HTTP không được tính là PASS GUI. Dùng dữ liệu QA riêng, không xóa/sửa truyện thật để thử. Ghi ngày giờ, actor, build/JDK, ảnh màn hình, kết quả API/SQL nếu ca yêu cầu. Mọi hàng US-00..US-18 phải được ghi PASS/FAIL/BLOCKED theo kết quả thực tế.

## Chuẩn bị và cách chạy

1. Mở Maven parent **Comic Net** tại đường dẫn hiện tại trong NetBeans; mở hai child **Comic Net Backend** và **Comic Net Desktop Swing**. Chọn JDK 21. Bấm phải **Comic Net Backend → Reload Project** nếu vừa cập nhật `nbactions.xml`.
2. Backend: bấm phải **Comic Net Backend → Run**. Mapping mới gọi `deploy/Start-Backend.ps1 -Mode Run -FromSource -UseLocalConfiguration` qua Maven, nạp cấu hình SQL/S3/SMTP private vào **tiến trình backend** rồi biên dịch source. Chờ `Tomcat started on port 8080`; không cần đặt `DB_USER` trong NetBeans, không nhập mật khẩu vào project properties. File `.env.example` không tự nạp. Nếu `-UseLocalConfiguration` báo không có file private, dùng `deploy/Start-Backend.ps1 -Mode Run -FromSource` trong PowerShell để nhập mật khẩu ẩn, hoặc chuẩn bị lại file local theo README; không dán mật khẩu vào chat/source.
3. Mở **Hệ thống** trong Swing sau khi bấm phải **Comic Net Desktop Swing → Run**. Bấm **Kiểm tra kết nối**; đợi Spring Boot và SQL Server ready. Backend phải chạy trước Swing. Nếu cổng 8080 đã có đúng backend Comic Net, giữ tiến trình đó, không khởi động bản thứ hai.
   Khi dùng backend QA ở cổng khác, đóng hẳn NetBeans trước rồi mở lại từ PowerShell với **chỉ biến API của Swing**: `$env:COMICNET_API_BASE_URL='http://localhost:8081/api/v1'; & 'C:\Program Files\Apache NetBeans\bin\netbeans64.exe'` (đổi `8081` theo backend QA thật). Sau đó Run child Swing và kiểm tra dòng API trong **Hệ thống**. Không đặt `DB_USER`/mật khẩu trong phiên NetBeans này.
4. Dùng ít nhất Guest, Reader, Creator sở hữu truyện, Creator không sở hữu, Moderator, Admin là **các tài khoản QA riêng**. Thử US-00 trên **database QA sạch riêng đã provision**, vì ComicNetDev đã có Admin và wizard one-time không thể thử lại hợp lệ. Launcher NetBeans mặc định luôn trỏ ComicNetDev: **không** chạy `-EnableSetup` trên database này để giả vờ thử setup mới; US-00 còn BLOCKED cho đến khi có backend QA cấu hình riêng và token setup riêng. Mail xác minh/reset lấy từ Mailpit `http://127.0.0.1:8025`, không dùng token thật của người dùng khác. Ca xóa, upload, backup, job restart dùng fixture/DB/S3 QA riêng.
5. Khi một ca thất bại, chụp cửa sổ + NetBeans Output, ghi Request ID nếu có và trạng thái dữ liệu trước/sau. Đừng tự đổi nhãn thành PASS vì thao tác tương tự đã qua MockMvc/integration test.

## Chuột, bàn phím, DPI và dialog — lặp cho các story liên quan

- **Chuột:** chọn hàng bảng/list, click một lần và hai lần nếu có hành vi; đổi tab khi request đang loading; kéo splitter và resize từ 1280×800 xuống tối thiểu 1024×640; max/restore; kiểm tra scroll không che nút. Quan sát nội dung cũ không ghi đè actor/view vừa đổi.
- **Bàn phím:** Tab/Shift+Tab qua trường và nút, Space chọn checkbox/button, Enter gửi form hoặc tìm kiếm, mũi tên di chuyển bảng/list; Reader dùng mũi tên trái/phải, ở **Hệ thống** dùng Alt+K kiểm tra và Alt+H hủy. Đừng giả định Enter/Esc tự xác nhận/hủy mọi `JOptionPane`: thử thực tế và ghi kết quả.
- **Dialog:** từng form `Lưu/Đóng`, JFileChooser upload, `Xác nhận xóa mềm`, `Xuất bản`, `Xóa lịch sử`, conflict/reapply, input bookmark/reject reason: dùng chuột Cancel/OK rồi bàn phím Tab+Enter/Esc. Xác nhận **Cancel/Esc không ghi SQL**; OK báo thành công chỉ sau REST thành công; nếu 409/412/503 phải có đường tải lại/thử lại phù hợp.
- **DPI:** Windows Settings → System → Display → Scale lần lượt **100%, 125%, 150%**; đóng/mở lại Swing sau mỗi lần đổi, ghi độ phân giải và scale, chụp cả màn 1280×800 và 1024×640, thử dialog ở mép cửa sổ. Kiểm font tiếng Việt, focus ring, tương phản, nút/scrollbar/cột bảng không bị cắt.
- **Lỗi kết nối:** trên fixture QA, tạm dừng backend rồi dùng **Hệ thống → Kiểm tra kết nối** và một thao tác đọc; khởi động lại rồi thử lại. Chờ network chậm và đổi tab/actor để kiểm response cũ không xuất hiện trên phiên mới. Không tắt SQL/RustFS production để thử.

Ghi kết quả từng hàng theo mẫu: `US-xx | actor/fixture | JDK/build | DPI/window | bước | expected | actual | screenshot/log/requestId | SQL trước/sau | PASS/FAIL/BLOCKED`. Chỉ chuyển PASS khi toàn bộ AC bắt buộc của hàng đã được thực hiện và đạt.
